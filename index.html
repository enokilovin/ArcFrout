THEORETICAL WORKING DIRECTORY

赤石基礎論

Minecraft Java Editionにおける論理メカニズムと遅延フェーズの体系的考察

1. 序論と基本理念

本研究サイトは、Minecraft Java Editionにおけるレッドストーンロジック（赤石回路）の挙動を、単なるゲームの「仕様」としてではなく、厳密な処理フェーズと遅延の論理体系として再構築する試みである。

特に、信号の伝播に伴う内部処理の優先順位や、ゲームティック内における処理順序の衝突を解消するための、新しい標準表記体系の確立を目指す。

2. コンポーネントの分類体系

回路を構成する各要素は、その処理のタイミングとゲーム内エンジンへの登録挙動に基づき、大きく以下の3つのカテゴリに厳密に分類される。

分類コード コンポーネント群 (一例) 主な処理特徴
PLC (PhaselessComponent) レッドストーンワイヤー、トーチ等 ティックを消費せず、即座にブロックアップデートを周囲に伝播させる。
STC (ScheduleTickComponent) リピーター、コンパレーター等 TileTick（予約リスト）に登録され、指定されたゲームティック後に処理を実行する。
BEC (BlockEventComponent) ピストン、ドロッパー等 ブロックイベントとしてキューに非同期処理され、固有の処理フェーズで動作する。

3. RSC記法によるタイムライン定義

信号強度の遷移および予約リストのシミュレーションを記述するため、従来の曖昧な表記を排し、簡素かつ厳密なクロノグラム（時系列チャート）表記を採用する。以下は、パルス入力時における特定ノードの応答特性である。

[RSC v3.00 - Timeline Analysis]
Tick  : 00  01  02  03  04  05
Input : __/‾‾‾‾\____________  (2GT Pulse)
NodeA : ____/‾‾‾‾\__________  (PLC Delay)
NodeB : ________/‾‾‾‾\______  (STC 1del)
Phase : [BEC-Processing-Window]

基本方程式の一例として、信号変化のトリガー条件は、近傍アップデート関数を f(u)、信号強度を P と置いたとき、以下のように記述される。

ΔP = f(u) × Σ(Trigger_i)
